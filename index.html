Gaussian splats with MPM physics

A Gaussian splat object simulated with the material point method, running on your GPU in this page. Pick a material and the object drops onto the floor. Drag to orbit, and click or tap to poke it. You can also load your own 3DGS .ply file.

This browser doesn't support WebGPU, so the demo can't run here. Recent Chrome, Edge, Safari and Firefox all support it.

Simulation

Every splat is an MLS-MPM particle on a 64³ grid, with APIC transfers and fixed-point atomic scatter, like the fluid on the home page. Jelly uses fixed-corotated elasticity. Sand uses Drucker-Prager plasticity, snow uses the Stomakhin hardening model, and liquid keeps only the volume change. Each particle carries a deformation gradient F, and a 3×3 SVD built on Jacobi eigen-iterations runs in WGSL every substep.

Trained splats only cover the surface, so the object is voxelised and the inside is filled with small round splats coloured from the nearest surface splat. A voxel counts as inside when it can see the surface in at least five of the six axis directions, which copes with the holes and missing underside of a real scan. Without them, an object made of surface splats would collapse like a paper shell, and sand or liquid would show a hollow inside.

Deforming the splats

Each splat's 3D covariance moves with the material: Σ = F Σ₀ Fᵀ, the approach from PhysGaussian (Xie et al., CVPR 2024). A splat stretches, squashes and rotates with the material around it. Sand and snow keep only the elastic part of F, so grains slide past each other without smearing.

Rendering

A compute pass projects each 3D covariance to a screen-space ellipse (EWA splatting). Splats are depth-sorted back to front every frame with the key-value radix sort from the sorting demo, on 16-bit keys in four passes, then drawn as alpha-blended quads.

Colour uses spherical-harmonic degree 0 only. Files over the splat limit are sampled down, favouring large opaque splats and growing the ones that are kept so the surface stays covered.
